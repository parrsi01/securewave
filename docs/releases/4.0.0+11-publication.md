## Public delivery verification

The [download page](https://www.securewaveapp.com/download.html) uses the updated
selector. The following catalogs each returned exactly one available entry,
version 4.0.0+11, architecture ARM64, with the expected source and checksum:

- `/api/downloads`
- `/api/downloads/list`
- `/downloads/manifest.json`
- `/static/downloads/manifest.json`

A complete HTTPS fetch of
`/downloads/securewave-vpn_4.0.0+11_arm64.deb` matched the package SHA-256.
Each of the six superseded files returned HTTP 404 under all three former
serving paths: `/downloads/`, `/static/downloads/`, and `/api/downloads/file/`.
That is 18 negative public URL checks, including the former direct-static
access path that bypassed the manifest allowlist.

The retired files are the old ARM64 Debian package, ARM64 app ZIP, x64 Linux
tarball, Apple handoff ZIP, macOS demo ZIP, and old install script. They were
moved to a root-private recovery directory on the existing production host:
`/var/backups/securewave-downloads-20261004T234622Z/retired/`. Nothing was
deleted. The same backup contains the prior manifest and the three original
website/download source files.

ARM64 platform detection recommends the new package. x86-64 Linux, Windows,
and macOS detection return no incompatible recommendation. A code-level check
of the live JavaScript also passed architecture selection and current card
rendering. The download page references a versioned JavaScript URL to refresh
cached clients. A browser connector was unavailable, so a visual browser
inspection was not claimed.
